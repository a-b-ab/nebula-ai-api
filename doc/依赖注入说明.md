# Go 语言依赖注入

## 什么是依赖？

一个结构体要完成功能，**必须使用到的其他接口或结构体**。

---

## ❌ 不使用依赖注入

```go
type UserService struct {
    db *sql.DB  // 自己创建
}

func NewUserService() *UserService {
    db, _ := sql.Open("mysql", "dsn")  // 硬编码
    return &UserService{db: db}
}
```

**问题**：强耦合、难测试、难替换

---

## ✅ 使用依赖注入

```go
type UserRepository interface {
    FindByID(ctx context.Context, id int) (*User, error)
}

type UserService struct {
    repo UserRepository  // 依赖抽象
}

// 通过构造函数注入依赖
func NewUserService(repo UserRepository) *UserService {
    return &UserService{repo: repo}
}

func (s *UserService) GetUser(ctx context.Context, id int) (*User, error) {
    return s.repo.FindByID(ctx, id)
}
```

---

## 常见依赖类型

| 类型 | 示例 |
|-----|------|
| 数据库 | `*sql.DB`, `Repository` 接口 |
| 外部服务 | `EmailService`, `PaymentGateway` |
| 缓存 | `Redis`, `Cache` 接口 |
| 配置 | `Config` 接口 |
| 日志 | `Logger` 接口 |

## 实战示例

```go
// 接口定义
type UserRepository interface {
    FindByID(ctx context.Context, id int) (*User, error)
}

// MySQL 实现
type MySQLUserRepository struct {
    db *sql.DB
}

func (r *MySQLUserRepository) FindByID(ctx context.Context, id int) (*User, error) {
    var user User
    err := r.db.QueryRowContext(ctx, "SELECT * FROM users WHERE id = ?", id).Scan(&user)
    return &user, err
}

// 内存实现（用于测试）
type InMemoryUserRepository struct {
    users map[int]*User
}

func (r *InMemoryUserRepository) FindByID(ctx context.Context, id int) (*User, error) {
    user, ok := r.users[id]
    if !ok {
        return nil, errors.New("not found")
    }
    return user, nil
}

// 业务逻辑（只依赖接口）
type AuthService struct {
    userRepo UserRepository
}

func NewAuthService(repo UserRepository) *AuthService {
    return &AuthService{userRepo: repo}
}

func (s *AuthService) Login(ctx context.Context, userID int) (*User, error) {
    return s.userRepo.FindByID(ctx, userID)
}
```

---

## 使用对比

```go
// 生产环境
db, _ := sql.Open("mysql", "production_dsn")
repo := &MySQLUserRepository{db: db}
authService := NewAuthService(repo)

// 测试环境
fakeRepo := &InMemoryUserRepository{users: map[int]*User{1: {ID: 1, Name: "Test"}}}
authService := NewAuthService(fakeRepo)
```

## 总结

| 概念 | Go 体现 |
|------|---------|
| **依赖** | 结构体中的接口字段 |
| **注入** | 通过构造函数传入 |
| **解耦** | 依赖接口，不依赖实现 |

**核心思想**：不要自己创建依赖，从外部传入。让代码可测试、可替换、可维护。

# 面试问答
1. 依赖注入就是把一个对象需要的外部依赖，通过构造函数传入，而不是让它在内部自己创建
2. 不用依赖注入：
  - UserService 里自己 new DB()
  - 强耦合，数据库换了要改代码
  - 测试时没法替换成 mock
  用了依赖注入：
  - 只依赖接口 UserRepository
  - 生产环境用 MySQL 实现
  - 测试环境用内存实现
3. 控制反转 -- 对象不再自己控制依赖的创建，而是交给外部（调用者）来提供

## 一句话
"比如我有一个 UserService，它需要查数据库。不好的做法是让 UserService 自己去创建 DB 连接，这样代码和数据库强绑定，单元测试时也没法替换。依赖注入的做法是：定义一个 UserRepository 接口，让 UserService只依赖这个接口，然后通过构造函数把具体的实现（比如 MySQL 或内存实现）传进来。这样业务逻辑和具体实现就解耦了，测试时可以轻松换成 mock 实现。"

## 依赖倒置的原则
高层模块不应该依赖底层模块，都应依赖抽象

## 设计思想的本质
应用入口main.go是统一管理所有依赖的创建和装配，这是控制中心
