# 任务模块：当前支持的能力

本文记录当前代码已经实现的任务能力和 HTTP 接口。任务用于异步处理文章 AI 优化：请求创建任务后，由后端进程内的 worker 执行，客户端通过查询接口查看结果。接口路径以 `/api` 开头。

## 当前能力

| 能力 | 当前实现 |
| --- | --- |
| 创建任务 | 通过文章优化接口创建 `article_optimize` 任务；先检查文章是否存在 |
| 避免重复创建 | 同一文章已有 `pending` 或 `processing` 的优化任务时，返回该任务 |
| 后台执行 | 服务启动时运行一个 worker，每 2 秒取出一条最早创建的 `pending` 任务执行 |
| 查询任务 | 查询任务列表或详情；列表可按文章 ID 筛选 |
| 记录结果 | 保存状态、开始与结束时间、优化结果或错误信息 |

目前 `article_publish` 仅在任务类型常量中定义，没有创建接口和执行分支。`canceled` 仅在状态常量中定义，没有取消接口；`max_retries` 创建时设为 3，但当前没有自动重试逻辑。服务启动时使用 `FakeArticleOptimizer`，优化结果是模拟内容。

## HTTP 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/articles/:id/optimize` | 为指定文章创建优化任务，或返回已有的运行中任务 |
| GET | `/api/tasks` | 分页查询任务，可按 `article_id` 筛选 |
| GET | `/api/tasks/:id` | 查询任务详情 |

除错误响应外，成功时均为 HTTP 200，统一格式为 `{"code":0,"message":"成功","data":...}`。错误响应为 `{"code":HTTP状态码,"message":"错误信息"}`。`:id` 为十进制无符号整数。

### 创建文章优化任务

`POST /api/articles/123/optimize` 不需要请求体。文章 ID 无效或文章不存在时返回 400。成功时 `data` 是任务对象；新任务的 `type` 为 `article_optimize`、`status` 为 `pending`、`article_id` 为目标文章 ID、`payload` 为包含文章 ID 的 JSON 字符串、`max_retries` 为 3。已有同一文章的 `pending` 或 `processing` 优化任务时，返回已有任务。HTTP 成功只表示任务已创建或复用，不表示优化完成。

### 查询任务列表

`GET /api/tasks?page=1&page_size=10&article_id=123`

| 查询参数 | 说明 |
| --- | --- |
| `page` | 默认 1；小于 1 时改为 1 |
| `page_size` | 默认 10；小于 1 时改为 10，大于 100 时改为 100 |
| `article_id` | 可选；提供后按文章 ID 精确筛选 |

按创建时间倒序返回，`data` 是分页对象：

```json
{"code":0,"message":"成功","data":{"data":[],"total":0,"page":1,"page_size":10}}
```

查询组件会读取 `status`、`keyword`、`sort_by`、`sort_order`，但任务列表目前不使用这些参数。当前处理函数在 `article_id` 解析失败或数据库查询失败后没有立即返回，可能在错误响应后继续写入成功响应，造成响应体异常；调用方应使用合法的文章 ID。

### 查询任务详情

`GET /api/tasks/:id` 返回单个任务对象。ID 格式错误返回 400，任务不存在返回 404。任务对象的字段如下：

| 字段 | 含义 |
| --- | --- |
| `id`、`type`、`status`、`article_id` | 任务标识、类型、状态和关联文章 |
| `payload` | 输入 JSON，以字符串形式返回；为 `nil` 时省略 |
| `result` | 执行结果 JSON，以字符串形式返回；为 `nil` 时省略 |
| `error` | 失败原因；无错误时为空字符串 |
| `started_at`、`finished_at` | 开始和结束时间；尚未发生时为 `null` |
| `created_at`、`updated_at` | 创建和更新时间 |
| `max_retries` | 保存的最大重试次数；当前不会触发重试 |
| `article` | 关联文章；当前查询没有预加载，通常为 `null` |

## 执行流程与状态

```text
POST /api/articles/:id/optimize
  → 写入 pending 任务
  → worker 每 2 秒选取最早的 pending 任务
  → 标记 processing，写入 started_at
  → 执行文章优化并写回文章
  → 成功：标记 completed，写入 result、finished_at
  → 失败：标记 failed，写入 error、finished_at
```

优化成功后，文章会更新为 `ai_optimized=true`、`status=1`（已优化）；优化器返回的非空标题、摘要、正文和非空标签列表也会写回文章，标签以逗号拼接。客户端可轮询 `GET /api/tasks/:id`，在任务完成后再查询文章详情。

当前 worker 为进程内单协程轮询，每次取一条任务。代码没有实现任务重试、取消、手动重跑或并发抢占保护。旧的 [任务系统设计文档](../task_system_design.md) 包含方案设想；以上内容以现有代码为准。
